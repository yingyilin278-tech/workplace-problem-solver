# 求职子域集成架构

## 目的

把外部 GitHub 求职类 skill 抽象成你这个 `workplace-problem-solver` 的求职子域，而不是把仓库名字简单堆进来。

这里吸收的是它们**主要解决的问题、输入输出结构、决策节点和优化闭环**。

## 求职子域如何挂进当前职场 skill

当前 `workplace-problem-solver` 原本更偏在职问题，核心是 C1-C12。

现在新增一层求职子域 J1-J7：

- `J1` 方向定位与求职策略
- `J2` 经历盘点与素材库
- `J3` JD 解析与简历定制
- `J4` 自我介绍与项目叙事
- `J5` 面试准备与模拟追问
- `J6` offer 比较与谈薪决策
- `J7` 面试复盘与下一轮优化

这层不是替代 C1-C12，而是和它们并行：

- 问“领导突然加活怎么办” -> 走 C1
- 问“我该投产品还是运营” -> 走 J1
- 问“这个 JD 怎么改简历” -> 走 J3
- 问“二面为什么挂了” -> 走 J7
- 问“拿到两个 offer 怎么选” -> 走 J6

## 判题逻辑

收到一个问题时，先判定它属于哪一类问题，而不是先输出建议。

### 1. 先分在职问题还是求职问题

若用户问题包含以下信号，优先进入求职子域：

- `简历`
- `JD`
- `投递`
- `面试`
- `自我介绍`
- `项目经历怎么讲`
- `offer`
- `谈薪`
- `校招`
- `社招`
- `转行找工作`

否则默认先按 C1-C12 做在职问题分类。

### 2. 再判定属于哪个 J 类

| 子类 | 典型问法 | 优先调用的问题框架 |
|---|---|---|
| J1 | 我适合投什么、要不要转岗找工作、先投大厂还是中厂 | 方向、约束、筹码、时间窗 |
| J2 | 我经历很乱、不会写、哪些经历能用 | 事实盘点、结果证据、角色责任 |
| J3 | 这个 JD 怎么改简历、这份简历为什么过不了筛 | JD 要求、命中差距、定制改写 |
| J4 | 自我介绍怎么说、项目经历怎么讲更有说服力 | 故事主线、结果、难点、个人贡献 |
| J5 | 明天面试怎么准备、可能会问什么、怎么模拟 | 岗位题库、追问点、回答骨架、面试官视角 |
| J6 | 两个 offer 怎么选、怎么谈薪、要不要接 | 风险、成长、现金、品牌、可逆性 |
| J7 | 我为什么挂了、复盘怎么做、下一轮怎么补 | 失败节点、证据缺口、修正动作 |

## 当前 skill 会怎么帮用户解决

### A. 不是直接给答案，而是先判断“卡点在哪”

例如用户说：

> 我投了很多简历都没回音

不会直接输出“多投、多优化标题”。

而是先判断卡点更像：

1. 方向错了：J1  
2. 素材散、没有拿得出手的经历：J2  
3. 简历没有针对 JD 改：J3  
4. 表达弱，过了筛也讲不清：J4/J5

### B. 再用对应层解决

#### J1 层：判断投递策略问题

- 目标岗位是否清楚
- 是否有时间窗和约束
- 当前履历最强筹码是什么
- 是先求上岸、先保收入，还是追求方向切换

#### J2 层：整理经历素材

- 把经历拆成：背景、目标、动作、结果、证据
- 去掉只有职责没有结果的空经历
- 补出能用于简历和面试的素材底稿

#### J3 层：做 JD 匹配和简历改写

- 提取 JD 的硬要求、隐含要求、排序要求
- 找用户经历中对应证据
- 改写成“岗位语言”而不是“流水账语言”

#### J4 层：构建叙事

- 做 1 分钟自我介绍
- 做 3 个核心项目故事
- 每个故事都能回答：为什么做、怎么做、结果如何、你起了什么作用

#### J5 层：模拟面试

- 先准备高频问题
- 再准备追问和质疑
- 用面试官视角检查：
  - 真实吗
  - 有结果吗
  - 有细节吗
  - 经得起追问吗

#### J6 层：做 offer / 谈薪决策

- 比较现金、岗位天花板、团队、品牌、成长和风险
- 不只看工资，也看可逆性和下一跳价值

#### J7 层：把失败复盘回灌

- 挂在哪轮
- 是简历不过筛、表达弱、项目深度不够、还是岗位匹配错
- 复盘结论反写进 J1/J3/J4/J5

## 这套架构的实际闭环

用户每提一个求职问题，这个 skill 会按下面顺序处理：

1. 先分 `在职问题` 还是 `求职问题`
2. 若是求职问题，再分到 `J1-J7`
3. 收集最少必要信息
4. 判断当前真正卡点
5. 输出五段结果：
   - `判断`
   - `建议`
   - `话术`
   - `后续`
   - `风险`
6. 若问题未解决，把结果回灌给上游层：
   - 简历不过筛 -> 回灌 J1/J3
   - 面试挂掉 -> 回灌 J4/J5/J7
   - offer 不会选 -> 回灌 J1/J6

## 接入原则

- 不把外部 skill 当成绝对真理。
- 只吸收它们对“问题定义、输入输出、优化闭环”的处理方式。
- 用户最终看到的仍然是统一的 `workplace-problem-solver` 五段式输出，而不是六个外部 skill 拼盘。
