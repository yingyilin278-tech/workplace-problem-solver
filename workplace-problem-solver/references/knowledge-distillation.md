# 知识蒸馏规范

目标不是“读过很多”，而是把来源变成在具体职场场景中可检索、可验证、可执行的知识。

## 来源优先级

1. 法规、制度、原始研究、作者原文、完整演讲或访谈。
2. 高质量专业书籍、系统综述、权威课程。
3. 可靠的二手分析。
4. 短视频、切片、语录图和无来源转述只能作为线索。

任何来源都不能因作者知名而自动变成事实。

## 单份资料处理流程

1. 登记元数据：标题、作者、类型、日期、链接或本地路径、版权/使用限制。
2. 提取主张：每条只表达一个可判断的观点。
3. 标证据：原始数据、案例、作者经验、观点或推测。
4. 转成场景：这条知识解决哪类职场问题。
5. 转成动作：用户今天能做什么、能说什么、要记录什么。
6. 写边界：不适用场景、反例、文化和组织差异。
7. 交叉核验：高风险建议至少寻找一个独立来源或反面证据。
8. 生成知识卡，并登记目录。

## 视频处理

优先取得合法字幕或用户有权处理的转写稿。保留时间戳。区分：

- 讲者明确主张
- 主持人或剪辑者的框定
- 案例描述
- 可验证事实
- 修辞和情绪表达

不要根据短切片推断完整立场。

## 知识卡字段

每张卡必须包含：

- 书库 ID、作者角色、版本和启用等级
- 来源与证据等级
- 适用国家、组织环境和角色
- 核心主张
- 适用场景
- 诊断问题
- 判断规则：可写成“如果—那么—除非”
- 行动步骤：按发生顺序，可在现实中执行
- 可直接使用的话术：说明对象、渠道和时机
- 失败信号与边界
- 反例、失败案例或争议
- 关联问题标签
- 与其他来源的冲突
- 经验证的案例 ID 和失败案例 ID

可运行：

```bash
python3 scripts/new_knowledge_card.py \
  --title "来源标题" \
  --creator "作者或讲者" \
  --source-type book \
  --source "合法链接或本地路径" \
  --output references/knowledge/source-slug.md
```

## 蒸馏质量门槛

一张卡只有同时具备以下五项才可进入“可用”状态：

1. 至少一条可判断的规则。
2. 至少一个现实行动步骤。
3. 至少一段可改写的话术。
4. 至少一个反例或不适用条件。
5. 可回查的来源与证据状态。

不收录只有名言、没有适用条件的卡片。不把单个成功者经验写成普遍规律。不把相关性写成因果。不用未经核验的心理学标签解释所有职场行为。摘要级蒸馏必须标明，不能伪装成全文结论。

书籍启用状态按 `book-library.md` 管理：

1. L0：只登记书目，禁止进入回答。
2. L1：核验官方信息，只能生成待验证假设。
3. L2：完成规则、行动、话术、反例和边界蒸馏，可进入案例测试。
4. L3：通过案例测试和人工复核，才可稳定影响回答。

同一问题最多使用 3 本核心书、2 本补充书和 1 本反方书。若书籍规则冲突，必须比较适用条件、权力差、行动可逆性和证据强度，不做简单投票。

## 版权控制

知识卡以概括、分析和少量必要引文为主。不要保存整本书、付费课程全文或大段受版权保护的字幕，除非用户拥有并明确授权，且使用方式合法。
